# foxkit · 专用浏览器工具

给日常上网准备的一个独立小工具：一个专用的 Firefox 浏览器 + 本地网络通道，
浏览器和它的数据都放在工具自己的文件夹里（放普通文件夹或 U 盘都行），不碰系统设置，
不往外上传任何东西。用完关掉，电脑上不留常驻服务。

## 它解决什么问题

- **数据隔离**：专用浏览器有自己独立的数据目录，不和日常浏览器混用，
  不登录浏览器账号，历史、Cookie、登录状态只存在工具文件夹里。
- **网络安全**：浏览器的流量只走你自己的节点出去；本工具不改系统代理，
  关掉工具，其他程序的网络不受影响。
- **隐私**：节点信息和浏览器数据只保存在本地，没有任何服务器收集它们。
  本仓库里也只有代码和空白模板，不含任何人的节点信息。

## 支持范围

- 节点协议：支持 sing-box 的协议（内核为官方 sing-box，按需自动下载与更新）。
- SOCKS / HTTP 代理地址也能直接用：
  - 不带账号密码的，浏览器直连，不需要下载内核；
  - 带账号密码的，由内核代登录后转发（浏览器本身不支持 SOCKS 账号认证）。
- 节点链接、订阅链接、一行一个的裸 SOCKS（`地址:端口` 或 `地址:端口:用户名:密码`）都能导入。

## 运行前要准备什么（先看这里）

工具放在一个**能写文件的文件夹**里就行（普通文件夹或 U 盘，别放系统目录），
建议至少留 1 GB 空间。两个版本要备的东西不一样：

### 程序版：起步只需要 `foxkit.exe` 一个文件

| 要备的东西 | 怎么来 | 备注 |
|---|---|---|
| `foxkit.exe` | 放进一个空文件夹，双击打开 | 起步就这一个文件，其余目录它自己建 |
| 节点链接 | 打开后点「导入」粘贴 | 没有节点，什么都启动不了 |
| sing-box 内核 | 需要时点程序里的「准备内核」，自动从 sing-box 官方 GitHub 下载 | 只有协议节点和带账号密码的代理需要内核；**无账号密码的 SOCKS 不需要、不会下载**。下载这一步要能联网打开 GitHub |
| Firefox 浏览器 | 用电脑上**已装好的官方 Firefox**；想做成便携的，点「准备浏览器」，它会把已装 Firefox 的程序复制进工具包 | 程序**不会下载 Firefox**；电脑上没装 Firefox 的，先装官方版再点「准备浏览器」。装了 Firefox 但不复制，也能直接用，只是换台没装 Firefox 的电脑就跑不了 |

内核自动下载不成功时的兜底：把官方 sing-box 安装包解压出的 `sing-box.exe`
和 `libcronet.dll` 手动放进 `Surf/core/`，程序一样认。

都备好后，文件夹长这样（`ff-data`、`config.json` 是自动生成的，不用手动建）：

```
工具文件夹/
├─ foxkit.exe
├─ nodes.txt、node.txt                      ← 导入的节点，自动生成
└─ Surf/
   ├─ core/sing-box.exe（+ libcronet.dll）   ← 需要内核的节点才有
   ├─ Firefox/firefox.exe（+ 整套程序文件）  ← 点过「准备浏览器」才有
   ├─ ff-data/                               ← 浏览器数据，自动生成
   └─ config.json                            ← 启动时按当前节点生成
```

### 脚本版：三样东西先备齐，脚本自己不下载

脚本版**不下载任何东西**，双击 `Start.bat` 之前先备齐：

1. **浏览器**：`Surf/Firefox/firefox.exe` 存在，且是整套程序文件（不是单个 exe）。
2. **内核**：用到协议节点或带账号密码的代理时，`Surf/core/sing-box.exe`
   （连同 `libcronet.dll`）要先放好；只用无账号密码的 SOCKS 可以没有。
3. **节点**：填进脚本目录的 `node.txt`，一行一条。

每样东西从哪来、怎么放，见 `script/使用说明.md` 的准备清单。
最省事的办法：先用程序版在一台能联网、装了 Firefox 的电脑上把内核和浏览器
都备好，再把整个 `Surf` 文件夹拷到脚本版目录里。

## 使用方法（程序版）

主线是固定的四步：**导入 → 选中 → 测试（可选）→ 启动**。
前一步没完成，后一步的按钮是灰的，窗口上方会写明点不了的原因，照着提示做就行。

### 第一次使用（完整流程）

1. 把 `foxkit.exe` 放进一个空文件夹，双击打开。
   第一次运行 Windows 可能弹 SmartScreen「未知发布者」，点「更多信息 → 仍要运行」。
2. **导入节点**：把节点链接粘贴到第 1 步的框里，点「导入」。
   当场只验格式、不测连通，结果会告诉你成功几条、重复跳过几条、失败几条和失败原因；
   失败的条目会留在框里，改好后可以再点一次「导入」。
3. **选中节点**：在第 2 步的列表里点一条，再点「设为当前节点」（或直接双击它）。
   列表里带「▶ 当前」标记的就是当前节点。
4. **备内核**（需要时）：当前节点是协议节点或带账号密码的代理时，
   点「准备内核」，等它从官方 GitHub 下载完成（进度条走完、记录里出现
   「✓ 内核就绪」）。无账号密码的 SOCKS 节点跳过这步。
5. **备浏览器**（需要时）：电脑上装了 Firefox 就能直接用；想让工具包换台电脑也能跑，
   点工具行的「准备浏览器」，把已装 Firefox 的程序复制进工具包。
6. **启动**：点「▶ 启动浏览器」。内核先自检、启动，再打开专用 Firefox，
   浏览器打开就是走当前节点的网络，不用再改任何设置。
7. **用完停止**：点「■ 停止」，或直接关掉 foxkit 主窗口（关窗口也会停内核）。
   注意：走内核的节点，停止只停内核、**Firefox 不会自动关，它会随之断网，
   请自己关掉它**；直连的 SOCKS 节点没有内核可停，关掉 Firefox 就算结束。

日常使用就简单了：打开 foxkit →（节点和当前选择都记着）→ 点「启动」→ 用完「停止」。

### 导入节点的三种方法

- **粘贴导入**：节点链接、一行一个的裸 SOCKS、链接夹在一段文字里、甚至整段
  订阅原文（base64 的那串）都能直接粘贴到导入框，程序自己把链接挑出来。
- **订阅导入**：点「订阅导入」，粘贴订阅地址，程序拉取后把里面的节点全部导入
  （已有的会按重复跳过）。拉取订阅走的是这台电脑当前的网络直连；
  订阅更新了，重新点一次「订阅导入」、再粘贴一次地址即可，没有自动更新。
- **手工放文件**：节点库就是工具文件夹根目录的 `nodes.txt`（一行一条链接），
  用记事本改它、把链接粘进去，重启程序一样认。当前节点记在 `node.txt` 里。

### 测试节点（和导入是两回事）

- 「测试选中」测当前选中的一条，「测试全部」逐条顺序测，中途可点「取消当前操作」停下。
- 结果直接写在列表里：`可用 · 123ms` 是通的和延迟；`不可用 · 原因` 是没通和为什么。
- 需要内核的节点，要先备好内核才能测。
- **测不通只提醒，不拦着启动** —— 测试用的目标站偶尔不准，真要用可以直接启动试。

### 管理节点

- **改名**：选中后点「改名」，起个好认的名字。
- **删除**：选中后点「删除」，会先问你确认；删的正好是当前节点，当前选择会一并清掉。
- **运行中锁定**：运行期间不能切换节点、不能删当前节点、不能更新内核，
  先点「停止」再做这些操作。
- **下载/测试中**：点「取消当前操作」可以中途停下，不会弄坏已导入的节点和已有内核。

### 内核管理

- 「准备内核」和「更新内核」是同一个动作：下载官方最新版，**验过能跑才换上，
  新版跑不起来会自动退回旧版**，旧版另外留了一份 `Surf/core/sing-box.exe.bak`。
- 下载要能联网打开 GitHub。连不上时不要反复点：把官方安装包解压出的
  `sing-box.exe` 和 `libcronet.dll` 手动放进 `Surf/core/` 效果一样。
- 万一更新后用着不对想退回：先停止运行，把 `Surf/core/sing-box.exe` 删掉，
  再把 `sing-box.exe.bak` 改名回 `sing-box.exe` 即可。
- 无账号密码的 SOCKS 节点全程用不到内核，不用管这一节。

### 换节点、换电脑、卸载

- **换节点**：停止 → 在列表里选另一条 → 设为当前 → 启动。不用重新导入、不用重装。
- **换电脑**：把整个工具文件夹拷过去就能接着用（节点、当前选择、浏览器登录状态
  都在里面）。前提是工具包里已经复制了 Firefox 程序（见「准备浏览器」），
  否则新电脑上要先装 Firefox。
- **备份**：拷一份工具文件夹就是备份；只想备份节点，单存根目录的 `nodes.txt` 也行。
- **卸载**：停止后直接删掉整个工具文件夹。没装服务、没写注册表、没改系统代理，
  删掉就干净了。

### 常见问题

| 现象 | 怎么办 |
|---|---|
| 「启动」按钮是灰的 | 看窗口上方的红字提示，它会直接写原因（先导入 / 先选节点 / 先准备内核 / 先准备浏览器 / 正在运行） |
| 准备内核失败、连不上 GitHub | 检查当前网络能不能打开 GitHub，稍后重试；或手动把 `sing-box.exe` 和 `libcronet.dll` 放进 `Surf/core/` |
| 测试显示不可用，但想试试 | 直接点启动。测试只提醒不拦路，以浏览器里实际能打开网页为准 |
| 启动失败，说本地端口未就绪 | 内核没正常起来。换一条节点再启动，或稍后重试；反复出现就重新点一次「准备内核」 |
| 点了停止，浏览器还在但上不了网 | 走内核的节点就这样：停止只停内核，浏览器随之断网，自己关掉即可；想继续用就回 foxkit 再点「启动」 |
| 浏览器里打开网页是直连、没走节点 | 确认是从 foxkit 点「启动」打开的那个专用 Firefox；自己平时开的 Firefox 不受本工具管理 |
| 订阅导入失败 | 先确认订阅地址完整、这台电脑能直连打开它；也可以把订阅内容整段粘贴到导入框里导入 |
| 上次没正常关机，这次打开提示清理了残留进程 | 这是自检在收拾上次异常退出留下的内核进程，正常现象，不用处理 |
| 杀毒软件报警或隔离了文件 | 把**工具文件夹**加进信任区/白名单（原因见下面「关于杀毒软件」一节） |

### 进阶：控制台模式（一般用不上）

在命令行里运行 `foxkit.exe -console` 是同一套功能的文字菜单（导入/订阅/选择/
测试/内核/启动/停止都在里面），界面起不来时可以应急。
`foxkit.exe -version` 看版本号，`foxkit.exe -selftest` 跑一遍内置自检（不联网）。

## 脚本版（备用）

`script/` 目录是同一套逻辑的脚本实现（`Start.bat` + `mkconfig.ps1`），
适合连 exe 都不方便运行的环境。脚本不下载任何东西、不绕过系统策略、不藏窗口，
内核和浏览器组件需要先用程序版备好（或手动放到 `script/Surf/` 对应位置）。
细节见 `script/使用说明.md`。脚本版支持的协议比程序版少几个（WireGuard、AnyTLS、SSH 请用程序版）。

## 注意事项

### 凭证和隐私

- **节点链接、订阅地址就是凭证**（里面含密钥/令牌）。根目录的 `nodes.txt`、
  `node.txt`、`subs.txt` 不要外发、不要截图给别人；找人帮忙看问题时先把链接打码。
- `Surf/ff-data/` 里是专用浏览器的**登录状态**，敏感程度仅次于节点：
  把整个工具文件夹拷给别人，等于把这些登录状态一起送出去。
- 专用 Firefox 里**不要登录 Firefox 账号**做同步 —— 那会把浏览数据同步到
  外部账号，破坏「数据只存本地」的隔离。
- 在别人或公共电脑上用完，请删掉整个工具文件夹。但要知道：Windows 对
  运行过的程序、插过的 U 盘会留系统层面的使用记录，删文件夹删不掉这类记录，
  介意的话只在自己的电脑上用。

### 使用习惯

- 同一台电脑**同一时间只跑一份** foxkit：本地入口固定用 `127.0.0.1:10808`，
  两份一起跑会抢端口；其他代理软件占着 10808 也会让它启动失败。
- 运行期间，这个本地入口只绑本机、不对局域网开放，但本机其他程序也能连它借道，
  所以**用完就停，不要一直开着**。
- 运行中不要移动、改名工具文件夹，也不要删 `Surf/` 里的文件。
- `Surf/config.json` 和 `Surf/ff-data/user.js` 每次启动按当前节点重新生成，
  **手改会被覆盖**；要换设置就换节点本身，不要改这两个文件。
- 内核只认官方来源：自动下载走 sing-box 官方 GitHub；手动放文件也只放
  官方安装包解压出的原文件，不要用来路不明的 `sing-box.exe`。

### 联网行为说明（工具自己会联网的只有三处）

1. **准备/更新内核**：访问 GitHub，取 sing-box 官方版本信息和安装包。
2. **订阅导入**：用这台电脑的网络直连你填写的订阅地址。
3. **测试节点**：经节点（直连节点就是直连）访问一个测试地址，看通不通和延迟。

除此之外没有数据上报、没有统计、没有 foxkit 自身的更新检查；
你的浏览流量只经过你自己的节点，本工具没有服务器、不经手你的流量。

## 已知限制

- 目前只支持 **Windows 64 位**（程序和内核都是 windows-amd64 版）。
- 传输方式为 XHTTP / SplitHTTP 的节点不在 sing-box 支持范围内：
  链接本身能导入，但在测试或启动生成配置时，程序会明确提示这类节点暂时用不了。
- 订阅**不会自动更新**，更新要手动重新导入一次（见「导入节点的三种方法」）。
- 连通性测试只用一个测试地址，偶尔会误判：显示不可用不等于节点真不能用，
  以启动后浏览器实际打开网页为准。
- 没有商业代码签名，SmartScreen 的「未知发布者」提示无法消除（见下面杀毒一节）。

## 数据都放在哪

工具文件夹内（节点文件在根目录，其余在 `Surf/` 目录）：

| 位置 | 内容 |
|---|---|
| `nodes.txt`、`node.txt`（工具文件夹根目录） | 你的节点（凭证，只存本地，别外发） |
| `Surf/ff-data/` | 专用浏览器的数据（登录状态在这里，敏感程度次于节点） |
| `Surf/core/` | sing-box 内核（官方原版文件） |
| `Surf/Firefox/` | 专用 Firefox 程序文件 |
| `Surf/config.json` | 每次启动按当前节点现生成的配置 |

把整个工具文件夹拷走就能在另一台电脑上接着用；换节点只改节点，不用重装。

## 关于杀毒软件

- 本工具未做商业代码签名，第一次运行时 Windows SmartScreen 可能提示
  「未知发布者」，点「更多信息 → 仍要运行」即可。
- sing-box 这类网络内核会被个别杀毒软件归为「风险工具」提示或隔离
  （不是病毒，是代理类工具的统一待遇）。遇到时把**工具文件夹**加入
  杀毒软件的信任区/白名单即可；发布包附 SHA256，可核对文件完整性。
- 本工具不加壳、不混淆、不自启、不装服务、不改系统代理，行为都在明处。

## 出问题时

先看程序窗口下方「记录」里的报错原文，多数问题的原因都写在里面。
需要找人帮忙时，把**报错原文**和 `foxkit.exe -selftest` 的自检结果一起发出来
定位最快 —— 注意只发报错行，节点链接原文不要发（那是凭证）。

内核是 [SagerNet/sing-box](https://github.com/SagerNet/sing-box) 的官方原版

## 自行构建

需要 Go 1.23+：

```powershell
cd app
go run github.com/josephspurrier/goversioninfo/cmd/goversioninfo@latest -icon=foxkit.ico -manifest=foxkit.manifest -o=foxkit_windows.syso
go build -ldflags="-H windowsgui" -o foxkit.exe .
```

`foxkit_windows.syso`（图标与版本信息）是构建时生成的，不入库；不生成也能构建，只是没有图标。
